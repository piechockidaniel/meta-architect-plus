## Inspiration

Choosing where to run a business application affects costs, data location, operational responsibility and recovery. Those choices are hard to compare when assumptions are scattered across documents. Architecture Decision Workspace brings the alternatives into a seated spatial workspace so people can inspect trade-offs and record why they chose an option.

## What it does

Start with a new product in an existing organization or a greenfield product. Describe the product, acknowledge the summary, confirm constraints and compare cloud, on-premise and hybrid options. Inspect components and findings in panels and spatial diagrams, change an assumption, then export an architecture diagram and Markdown decision record with a rationale.

Findings distinguish unknown requirements from failures. The deterministic engine remains usable without an AI service. Local autosave and resume support short working sessions.

## How it was built

TypeScript, Meta Immersive Web SDK, three.js and Horizon UI components. The decision engine and session model are separated from the spatial runtime. An in-VR keyboard supports hands-first text entry. Panels provide recentering, text scaling and visible status feedback. The comparison islands reflect the same underlying decisions as the panel view.

Local unit, markup, coverage and browser runtime checks support development. The final submission must add actual Quest 3 results and identify any emulator footage truthfully.
